================================================================================
                    CAMPUS GUIDE 3D — UI DOCUMENTATION
================================================================================

PROJECT OVERVIEW
--------------------------------------------------------------------------------
Name        : Campus Guide 3D
Purpose     : Production-ready web-based digital twin of the college campus.
              Students, visitors, faculty, and administrators can search locations,
              explore the campus cinematically, and navigate interactively in 3D
              — all inside the browser.
Tech Stack  : Next.js 15 · TypeScript · Tailwind CSS v4 · Framer Motion ·
              React Three Fiber · Rapier · ecctrl · Zustand · MongoDB Atlas ·
              NextAuth · Zod · Lucide React
Monorepo    :
  blender/         — Source of truth; campus models originate here
  unity-prototype/ — Reference only; validated gameplay concepts
  docs/            — Architecture & system design
  data/            — Seed JSON datasets
  database/scripts/- MongoDB import/export utilities
  web-platform/    — Next.js 15 production application (PRIMARY UI PROJECT)
Asset Pipeline: Blender → Optimized GLB (Draco) → React Three Fiber → Vercel CDN
Single Auth. Campus Model: web-platform/public/models/campus.glb

1.3 TYPOGRAPHY
--------------------------------------------------------------------------------
Font Family  : Geist Sans (primary), Geist Mono (monospace)
Weights      : 400 (normal), 700 (bold), 800 (extra bold), 900 (black)
Tone Rules   : Headings → uppercase, bold, tight tracking
               Labels  → uppercase, font-bold, tracking-widest
               Body    → normal case, readable weight
               Data    → font-mono

1.4 SHADOWS & BORDERS
--------------------------------------------------------------------------------
Class              Shadow / Border Style
--------------------------------------------------------------------------------
neo-border         2px solid #0a0a0a
neo-shadow         4px 4px 0 0 #0a0a0a
neo-shadow-lg      6px 6px 0 0 #0a0a0a
neo-card           2px solid #0a0a0a + 4px 4px 0 0 #0a0a0a + white bg + p-4
neo-header-inner   3px solid #0a0a0a + 8px 8px 0 #0a0a0a + white bg + rounded-24px

Interaction pattern (all interactive elements):
  Hover     : translate(2px, 2px) + shadow reduces by 2px
  Active    : translate(3px, 3px) + shadow removed
  Focus     : 3px outline ring (focus-visible) with high contrast

1.5 MOTION
--------------------------------------------------------------------------------
Library    : Framer Motion (for animated interactions)
Durations  : 100ms hover/active transitions (CSS)
            120ms–240ms motion durations (Framer Motion)
Animation  : Button tap → whileTap={{ x: 2, y: 2 }}
             Search results → fade + slide up (opacity + translateY)
             Loading → progress percentage with @react-three/drei

1.6 RESPONSIVE BREAKPOINTS
--------------------------------------------------------------------------------
Breakpoint  Target                Behavior
--------------------------------------------------------------------------------
< 980px     Mobile nav            .neo-nav hidden, .neo-mobile-toggle shown
                                Mobile menu slides down with .open class
< 480px     Small mobile          .neo-logo-text hidden, reduced padding
                                .neo-header-inner gap reduced to 10px

1.7 ACCESSIBILITY STANDARDS
--------------------------------------------------------------------------------
- All interactive elements keyboard operable (Tab + Enter/Space)
- Focus-visible: 3px ring with contrast >= 3:1 against surface
- Body text contrast >= 4.5:1
- ARIA live regions for search results and route navigation
- Skip links for keyboard users
- role="status" on loading overlays
- role="alert" on error messages
- aria-label on icon-only buttons
- aria-pressed on toggle buttons (mode switcher)
- aria-current="page" on active nav links
- aria-live="polite" on dynamic content regions

4.1 APP STORE (useAppStore)
--------------------------------------------------------------------------------
Location  : src/store/use-app-store.ts
Purpose   : Global app-level state for interaction mode and scene readiness.
State     :
  mode           : InteractionMode ("explore" | "game")
  previousMode   : InteractionMode | null
  isSceneReady   : boolean
  isLoading      : boolean
  activePanel    : AppPanel ("search" | "info" | "navigation" | null)
Actions   :
  setMode(mode)               → switches mode, preserves previous
  setSceneReady(ready)        → updates both isSceneReady and isLoading
  setLoading(loading)         → updates isLoading
  togglePanel(panel)          → toggles panel open/closed

12. DATA FLOW & API INTEGRATION
================================================================================

API Endpoints (Consumed by UI):
  GET  /api/search?q=...                      → Search results
  POST /api/navigation/path                   → Route calculation
  POST /api/auth/register                     → Account creation
  POST /api/auth/forgot-password              → Password reset request
  POST /api/auth/reset-password               → Password reset (token)
  POST /api/auth/verify-email                 → Email verification
  POST /api/admin/change-password             → Forced password change
  GET  /api/admin/users                       → List users + audit logs
  POST /api/admin/users                       → Create sub admin
  PUT  /api/admin/users                       → Update sub admin
  DELETE /api/admin/users?id=...              → Delete sub admin
  POST /api/admin/import                      → Import data
  GET  /api/admin/export                      → Export data

Data Stores (Client-side Zustand):
  AppState       → App mode, loading, panels
  SearchState    → Query, results, recent searches
  NavigationState→ Active route, waypoints, navigation status
  WorldState     → Camera commands, focus targets
  PlayerState    → Player position, spawn point

================================================================================
15. KNOWN UI PATTERNS & CONVENTIONS
================================================================================

Button Strategy     : All actions use NeoButton with semantic variants.
                      Never use raw <button> without neo classes.
Card Strategy       : Content containers use NeoCard. Admin pages extend
                      with .e-{type} modifier classes.
Form Strategy       : Labels uppercase + bold, inputs with NeoInput,
                      errors in red-600, success in teal-800.
Navigation Strategy : Global header provides primary navigation. Campus
                      experience adds its own floating search dock.
Loading Strategy    : SceneLoader for 3D, button loading text for forms.
Accessibility       : Always include aria-labels on icon buttons, aria-live
                      on dynamic regions, skip links on long pages.
Motion Strategy     : Framer Motion for list animations + button taps.
                      CSS transitions for hover/active states.
Error Handling      : Inline error messages (never alert/confirm for UX errors).
                      Modal confirmations only for destructive actions (delete).
